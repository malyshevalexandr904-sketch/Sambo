# RATED_ONLY — все турниры рейтинговые

Статус: **реализовано** (2026-10-25). Решение заказчика: все соревнования на платформе рейтинговые, создаёт их только администратор платформы, организации подают заявки; формат проведения один; спортсмены делятся на дивизионы по возрасту; в кабинете спортсмена — дивизион и трекер Elo.

Связанные документы: [RATED_TOURNAMENT_FORMAT.md](RATED_TOURNAMENT_FORMAT.md), [RATING_ARCHITECTURE.md](RATING_ARCHITECTURE.md), [RATING_RULES.md](RATING_RULES.md).

## 1. Кто создаёт турнир

| Кто | Что может |
|---|---|
| Администратор платформы (`SUPER_ADMIN`, `PLATFORM_ADMIN`; право `competition.create_rated`) | Создаёт турниры без ограничений по числу (`POST /competitions`) для любой активной организации-организатора; рассматривает заявки организаций |
| Организация (`ORGANIZER`, `FEDERATION_ADMIN`, `CLUB_MANAGER`; право `competition.request`) | Подаёт заявку на проведение (`POST /competition-requests`), видит и отзывает свои заявки |
| Остальные | Не создают турниры и не подают заявок |

- Создание турнира кем-либо, кроме платформы, — 403 `RATED_COMPETITION_FORBIDDEN` (текст подсказывает про заявку).
- Турнир всегда `RATED`: при создании закрепляется действующая версия правил расчёта Elo (`CompetitionRatingConfig`). Поле `competitionType` в запросе принимает только `RATED`.
- Право организации `competition.create` заменено на `competition.request` (миграция данных `20261026100100_rated_only_access`).
- Создатель-платформа руководителем турнира не становится. Организатор (`ORGANIZER`) ведёт турнир своей организации по наследованию прав (▲), как и раньше.
- Тип турнира: перевести прежний нерейтинговый турнир в рейтинговый можно (`POST /admin/competitions/:id/rating`, `.../rating-type-change`); сделать турнир нерейтинговым — нельзя, 422 `NON_RATED_COMPETITION_FORBIDDEN`.

## 2. Заявка на проведение

`CompetitionRequest`: организация, автор, предложение (`proposal` — название, сроки, часовой пояс, окно регистрации, уровень, дисциплина, место организации, описание, контакты), ожидаемое число участников, комментарий для администратора.

| Статус | Как попадает | Кто |
|---|---|---|
| `SUBMITTED` | `POST /competition-requests` | организация (`competition.request`) |
| `APPROVED` | `POST /competition-requests/:id/approve` (If-Match) | платформа |
| `REJECTED` | `POST /competition-requests/:id/reject` с причиной (If-Match) | платформа |
| `WITHDRAWN` | `POST /competition-requests/:id/withdraw` (If-Match) | организация |

- Решение принимается один раз: повторное — 422 `COMPETITION_REQUEST_NOT_PENDING`.
- Одобрение в одной транзакции создаёт черновик рейтингового турнира по предложению (организатор — организация заявки) и связывает его с заявкой (`competition_request.competition_id`, CHECK: есть у одобренной и только у неё). Правила соревнований, категории, положение и публикацию готовят уже в турнире.
- Автор заявки ведёт свой турнир: если ролью в организации он турниром не управляет (федерация, клуб), ему выдаётся роль руководителя турнира — она действует в кабинете «Судья» (правило четырёх ролей кабинета). Организатор (`ORGANIZER`) управляет по наследованию, роль ему не нужна.
- Видимость: платформа — все заявки, организация — свои; чужая заявка — 404.
- Аудит: `competition_request.submitted`, `.withdrawn`, `.approved`, `.rejected`.
- Экраны: «Заявки на проведение» (`/competition-requests`, список с фильтром по статусу, у администратора по умолчанию — ожидающие), форма заявки (`/competition-requests/new`), карточка с решением (`/competition-requests/:id`). На странице турниров организация видит кнопку «Подать заявку на проведение», администратор — «Создать турнир».

## 3. Один формат проведения

Формат рейтингового турнира один — `SPECIAL_GROUP_RATED` ([RATED_TOURNAMENT_FORMAT.md](RATED_TOURNAMENT_FORMAT.md)): группы по рейтингу, распределение змейкой, выход в плей-офф.

- Жеребьёвка рейтингового турнира всегда предлагает и строит этот формат; другой формат в запросе — 400 `format_not_available`.
- Формат категории (`formatOverride`) рейтингового турнира задать нельзя (400 `format_not_available`); прежнее значение у категории больше не действует.
- Экран жеребьёвки показывает формат без выбора.
- Остальные форматы остаются в коде только для турниров, созданных до перехода (они `NON_RATED` и доигрываются по своим правилам).

## 4. Дивизионы по возрасту

`Division`: название, возраст «от» и «до» (включительно, пустая граница — без ограничения), пояснение. Удаление мягкое.

- Число дивизионов и границы задаёт администратор платформы (право `division.manage`): экран «Дивизионы» (`/admin/divisions`), `POST /admin/divisions`, `PATCH /admin/divisions/:id` (If-Match), `DELETE /admin/divisions/:id`. Границы не пересекаются — иначе 422 `DIVISION_OVERLAP`.
- Как считать возраст (`PUT /admin/divisions/age-policy`, хранится в `system_setting` `divisions.agePolicy`):
  - `BY_BIRTH_YEAR` (по умолчанию) — сколько лет исполняется в текущем году; переход в следующий дивизион 1 января;
  - `EXACT_ON_DATE` — полных лет на сегодня; переход в день рождения.
- Дивизион у спортсмена не хранится — вычисляется по дате рождения (сегодня — по Москве), поэтому меняется сам. Возраст вне всех дивизионов — «не определён».
- `GET /divisions` — любому вошедшему.
- Аудит: `division.created`, `.updated`, `.deleted`, `.policy_changed`.

Границы дивизионов заказчик определит позже — до этого список пуст, и кабинет показывает «дивизион не определён».

## 5. Кабинет спортсмена: дивизион и трекер Elo

`GET /athletes/:id/rating-progress` — тем, кто видит карточку спортсмена (сам спортсмен, подтверждённый представитель, тренер и клуб, платформа); иначе 404. Согласие на публикацию не требуется (это не публичная страница), соперники без согласия скрыты, как на сайте.

Ответ `AthleteRatingProgress`: дивизион с возрастом и правилом счёта, текущий рейтинг (уровень, лучший, схватки, победы и поражения) и последние 500 событий рейтинга по порядку — схватки и корректировки, у каждой рейтинг до и после, изменение, исход, соперник, турнир.

Экран:

- обзор кабинета в роли «Спортсмен» — «Мой дивизион и рейтинг»; в роли «Представитель спортсмена» — то же по каждому подтверждённому ребёнку;
- карточка спортсмена (`/athletes/:id`) — тот же блок для тренера и клуба;
- трекер Elo: по горизонтали — номер схватки (схватки одного дня не слипаются), по вертикали — рейтинг после схватки; первая точка — рейтинг до первой схватки. Победа — зелёная точка ●, поражение — красный треугольник ▼ (исход читается и без цвета). Наведение, касание и стрелки клавиатуры показывают схватку: дату, турнир, исход, соперника и изменение рейтинга. Под графиком — последние пять схваток списком.
