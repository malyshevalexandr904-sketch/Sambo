# RATED_TOURNAMENT_FORMAT — формат рейтингового турнира (группы + финальная часть)

Статус: **реализовано** (фазы 9–12, PR #35–#39): версия формата `rated-groups-v1` — `packages/contracts/src/rated-format.ts`. Решения заказчика: 40+ не делаем (2026-10-18), места в подгруппе Q-F4 и места ниже третьего Q-F5 (2026-10-19); остальное — по умолчаниям анализа (раздел 7).
С 2026-10-25 этот формат — единственный для новых турниров: все турниры рейтинговые ([RATED_ONLY.md](RATED_ONLY.md), 3).

Связанные документы: [RATING_RULES.md](RATING_RULES.md), [RATING_ARCHITECTURE.md](RATING_ARCHITECTURE.md).

Рейтинговый статус турнира (`RATED` / `NON_RATED`) и формат категории (`SPECIAL_GROUP_RATED`) — разные понятия: статус решает, меняется ли Elo; формат — как строится сетка. Рейтинговый турнир по умолчанию использует этот формат, но формат хранится в категории, как и сейчас (`CompetitionCategory.formatOverride`, `Draw.format`).

## 1. Правила по числу участников категории (G1, принятая редакция)

| Участников N | Групп | Размеры подгрупп | Выходят из подгруппы | Финальная часть | Схваток в финальной части |
|---|---|---|---|---|---|
| 1–2 | — | — | — | Сетка не строится: `INSUFFICIENT_PARTICIPANTS` (граница — правило формата, ТЗ 36) | — |
| 3–5 | 1 | N | — | Нет; круговая система, места — по итогам круга | 0 |
| 6–11 | 2 (А, Б) | 3–6, разница не больше 1 | 2 | 4: полуфиналы → финал | 3 |
| 12–23 | 4 (А–Г) | 3–6 | 2 | 8: четвертьфиналы → полуфиналы → финал | 7 |
| 24–39 | 8 (А–З) | 3–5 | 1 | 8: четвертьфиналы → полуфиналы → финал | 7 |
| 40+ | — | — | — | Пока не делаем (решение заказчика 2026-10-18): рейтинговая жеребьёвка отказывает с `TOO_MANY_PARTICIPANTS` | — |

Одинаково во всех источниках: **схватки за 3 место нет — оба проигравших полуфиналиста занимают 3 место** (G1 `O15`, `O24`, `O38`: «ПОБЕДИТЕЛИ СХВАТОК БОРЮТСЯ ЗА 1-2 МЕСТО, ПРОИГРАВШИЕ ЗАНИМАЮТ 3 МЕСТА»).

### 1.1 Размеры подгрупп (G1, столбцы `C:J`)

| N | Размеры | N | Размеры | N | Размеры |
|---|---|---|---|---|---|
| 6 | 3·3 | 14 | 4·4·3·3 | 24 | 3×8 |
| 7 | 4·3 | 15 | 4·4·4·3 | 25–31 | (N−24) подгрупп по 4, остальные по 3 |
| 8 | 4·4 | 16 | 4×4 | 32 | 4×8 |
| 9 | 5·4 | 17 | 5·4·4·4 | 33–39 | (N−32) подгрупп по 5, остальные по 4 |
| 10 | 5·5 | 18 | 5·5·4·4 | | |
| 11 | 5·6 | 19 | 5·5·5·4 | | |
| 12 | 3×4 | 20 | 5×4 | | |
| 13 | 4·3·3·3 | 21–23 | (N−20) подгрупп по 6, остальные по 5 | | |

Общее правило, которому соответствует вся таблица: `N` делится на `g` подгрупп с размерами `⌊N/g⌋` и `⌈N/g⌉`. Его же даёт распределение змейкой (раздел 2) — отдельной таблицы размеров в коде не нужно.

### 1.2 Схемы кругов подгруппы (G1 `N4:R11`, G5)

Номер — позиция в подгруппе (1 — высший посев). Схватки одного круга идут параллельно.

| Участников | Круг 1 | Круг 2 | Круг 3 | Круг 4 | Круг 5 |
|---|---|---|---|---|---|
| 3 | 1-2 | 1-3 | 3-2 | | |
| 4 | 1-2, 4-3 | 1-3, 2-4 | 1-4, 3-2 | | |
| 5 | 1-2, 5-4 | 1-3, 2-4 | 1-4, 3-5 | 1-5, 3-2 | 5-2, 4-3 |
| 6 | 1-2, 6-3, 5-4 | 1-3, 2-4, 6-5 | 1-4, 3-5, 2-6 | 1-5, 4-6, 3-2 | 1-6, 5-2, 4-3 |

Первая позиция пары — красный угол (так в бланках G5; Q-F6, принято по умолчанию). Порядок отличается от текущего генератора круговой системы платформы (`roundRobinPairs`, метод «круга»: для 3 участников — 2-3, 3-1, 1-2), поэтому схемы кругов — **данные правила формата**, а не алгоритм.

### 1.3 Финальная часть (G1 `N12:W45`)

Обозначение: «А1» — 1 место подгруппы А, «Б2» — 2 место подгруппы Б.

**6–11 (финал на 4):**

```
Полуфинал 1: А1 — Б2 ┐
                     ├─ Финал → 1 и 2 места; проигравшие полуфиналов — 3 и 3
Полуфинал 2: Б1 — А2 ┘
```

**12–23 (финал на 8):**

```
ЧФ1: А1 — Б2 ┐
             ├─ ПФ1 ┐
ЧФ2: В1 — Г2 ┘      │
                    ├─ Финал
ЧФ3: Б1 — А2 ┐      │
             ├─ ПФ2 ┘
ЧФ4: Г1 — В2 ┘
```

**24–39 (финал на 8, по одному из подгруппы):**

```
ЧФ1: А — Б ┐
           ├─ ПФ1 ┐
ЧФ2: В — Г ┘      │
                  ├─ Финал
ЧФ3: Д — Е ┐      │
           ├─ ПФ2 ┘
ЧФ4: Ж — З ┘
```

Победители подгрупп одной половины не встречаются до финала: «А1» и «Б1» — в разных половинах (12–23), «А1» и «Б1» — только в финале (6–11).

## 2. Распределение по подгруппам (посев)

- G3: «спортсмены сортируются по начальному рейтингу»; G4: «по группам спортсмены распределяются в зависимости от рейтинга автоматически».
- Номер посева = место по Elo **на момент жеребьёвки** (`TournamentSeed.ratingAtDraw`), 1 — высший рейтинг. Равный рейтинг — порядок по зерну жеребьёвки (существующий воспроизводимый PRNG, ADR-11).
- Распределение — **змейкой** (G1 `AC11:AJ38`, G2): посевы 1…g — в подгруппы А…, следующие g — в обратном порядке, и так далее. Пример 4 подгрупп: А — 1, 8, 9, 16, 17; Б — 2, 7, 10, 15, 18, 23; В — 3, 6, 11, 14, 19, 22; Г — 4, 5, 12, 13, 20, 21.
- Позиции внутри подгруппы — по возрастанию номера посева (1 — сильнейший), затем пары по схеме раздела 1.2.
- Разведение по клубам и регионам (есть в текущей жеребьёвке платформы) в источниках не упоминается; по умолчанию **не применяется** в рейтинговом формате (Q-F7).

| Общее место на границе выхода или среди вышедших | ТЗ 31 | Порядок задаёт главный судья с причиной (`GroupPlaceDecision`, `POST /api/v1/draws/:id/group-decisions`, право `result.amend`); действует последнее решение, сетка пересчитывается |

Порядок критериев совпадает с круговой системой платформы (`round-robin.ts`). **Elo для мест не используется** (ТЗ 22).

## 5. Конфигурация формата (`RatedTournamentFormatRule`)

Набор правил — данные версии формата, а не ветки `if (n === 6)`. Версия `rated-groups-v1` (`RATED_GROUPS_V1`; схема `RatedFormatConfig` проверяет согласованность: диапазоны подряд, размер финальной части, пары, схемы кругов для всех размеров подгрупп):

```jsonc
[
  { "minParticipants": 3,  "maxParticipants": 5,  "groupCount": 1, "qualifiersPerGroup": 0, "finalBracketSize": 0 },
  { "minParticipants": 6,  "maxParticipants": 11, "groupCount": 2, "qualifiersPerGroup": 2, "finalBracketSize": 4,
    "finalPairing": [["A1","B2"],["B1","A2"]] },
  { "minParticipants": 12, "maxParticipants": 23, "groupCount": 4, "qualifiersPerGroup": 2, "finalBracketSize": 8,
    "finalPairing": [["A1","B2"],["C1","D2"],["B1","A2"],["D1","C2"]] },
  { "minParticipants": 24, "maxParticipants": 39, "groupCount": 8, "qualifiersPerGroup": 1, "finalBracketSize": 8,
    "finalPairing": [["A1","B1"],["C1","D1"],["E1","F1"],["G1","H1"]] }
  // 40+: не поддерживается (решение заказчика 2026-10-18) — TOO_MANY_PARTICIPANTS
]
```

Общие параметры версии: `distribution: "SNAKE"`, `roundSchedules` (раздел 1.2, по размеру подгруппы), `thirdPlace: "BOTH_SEMIFINAL_LOSERS"`, `groupStandingRules: { criteria: [WINS, HEAD_TO_HEAD, CLEAN_WINS, SUPERIORITY_WINS], confirmed: true }`, `placementRules: { losers: { FINAL: 2, SEMIFINAL: 3, QUARTERFINAL: 5 }, nonQualifiers: BY_GROUP_POSITION, confirmed: true }`. Меньше 3 участников — `INSUFFICIENT_PARTICIPANTS`, больше 39 — `TOO_MANY_PARTICIPANTS`. Пара `finalPairing[i]` — четвертьфинал (или полуфинал) `i`; соседние пары сходятся в следующем круге.

## 6. Как это ложится на текущие сетки платформы

- Жеребьёвка `Draw` (формат `SPECIAL_GROUP_RATED`) хранит вход и `TournamentSeed` (посев + рейтинг на жеребьёвке).
- Подгруппа — `Bracket` с `kind = POOL` (по одному на подгруппу, `stageOrder` 1…g); финальная часть — `Bracket` с `kind = FINAL`.
- Узлы финала — `BracketNode` с источником `POOL_RANK`. Узел заполняется, когда подгруппа завершена и место занимает один участник; общее место ждёт решения главного судьи (раздел 3).
- Таблицы подгрупп отдельно не хранятся: они вычисляются из результатов схваток (`brackets/domain/group-standings.ts`) и показываются в сетке жеребьёвки.
- Места в финале — `placeForWinner` / `placeForLoser` узлов (как в олимпийской системе): финал — 1 / 2, полуфиналы — `placeForLoser = 3`.
- Схватки подгрупп и финала — обычные `Match`; рейтинг считается за каждую подтверждённую схватку, если турнир `RATED` (RATING_ARCHITECTURE.md, 6).
